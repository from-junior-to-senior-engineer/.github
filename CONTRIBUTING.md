> **Do not open pull requests that modify source code.**
> The code in each repo is intentionally left incomplete — it is the starting point for people who fork and practice on their own.
> Contributions are welcome on documentation, user stories, and project structure only.

# Contributing to From Junior to Senior Engineer

Thank you for considering a contribution.
This project exists because people like you take the time to improve resources for others.

---

## What you can contribute

### On existing repos
- Fix typos or unclear explanations in documentation
- Improve or add user stories in `docs/BACKLOG.md`
- Propose alternative architecture decisions with justification
- Add reference solution branches with documented reasoning
- Report inconsistencies between the code and the documentation

### New project repos
- Propose a new simulated project by opening an issue first
- Follow the repo structure convention described below
- Include a realistic business context, not just a technical exercise

---

## Repo structure convention

Every project repo must include:

```
README.md                   → business context, stack, quick start
docs/ARCHITECTURE.md        → initial architecture + known debt
docs/BACKLOG.md             → progressive user stories
docs/LEARNING_GUIDE.md      → structured training path
docs/REASONING_FRAMEWORK.md → interview-style Q&A for this project
docs/LEARNING_LOG.md        → empty template for personal journaling
```

---

## Naming convention for repos

```
{domain}-{context}-{language/stack}

examples:
order-management-java
notification-service-java
data-pipeline-python
auth-refactor-go
```

---

## How to submit a contribution

1. Fork the repo
2. Create a branch: `fix/description` or `feat/description`
3. Make your changes
4. Open a Pull Request with a clear description of what and why
5. Wait for review — we prioritize clarity and reasoning over perfection

---

## Tone and language

- All documentation and code must be in **English**
- Keep the tone honest and direct — we are not pretending to be experts
- Favor explanation over demonstration — the *why* matters more than the *what*

---

*If you are unsure whether your contribution fits, open an issue and ask.
That's always the right first step.*
