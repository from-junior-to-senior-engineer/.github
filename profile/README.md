# From Junior to Senior Engineer

> Real-world projects to learn how to think like an engineer, not like a student.

---

## The problem we address

Most learning resources teach syntax.
Tutorials give you clean codebases, simplified contexts, pre-solved problems.

Real work is different.

It's an undocumented legacy system that nobody wants to touch.
It's an architecture decision you have to justify under pressure.
It's a pull request to review without a safety net.
It's an interview question you've never faced in a real context.

**This gap between training and reality is what we close here.**

---

## What we offer

Simulated projects with:

- a **realistic business context** — no todo apps,
- **documented technical debt** as a starting point,
- a **progressive user story backlog** to implement,
- **architecture decisions to make and argue**,
- a **learning log** to normalize doubt and growth.

The goal is not to give you the right answer.
It's to train the thinking process that leads to a good answer.

---

## Who this is for

- Junior developers who want to grow structurally,
- Interns and apprentices preparing for their first real mission,
- Backend candidates preparing for technical interviews,
- Anyone who wants to move from "I write code" to "I design and reason".

## How to use these projects

Each repo follows the same structure:

```
README.md                   → context, stack, quick start
docs/ARCHITECTURE.md        → documented technical decisions
docs/BACKLOG.md             → user stories to implement
docs/LEARNING_GUIDE.md      → structured training path
docs/REASONING_FRAMEWORK.md → interview-style Q&A
docs/LEARNING_LOG.md        → your personal progress journal
```

**Recommended approach:**

1. Read the README and understand the business context
2. Read the backlog and pick a user story
3. Audit the existing code before touching anything
4. Implement while documenting your decisions
5. Compare with reference branches when available

## Philosophy

```
A junior who reasons clearly
outperforms a senior who just recites.
```

Technical confidence doesn't come from accumulated experience alone.
It comes from the quality of your reasoning when facing the unknown.

That reasoning is what we train here.
